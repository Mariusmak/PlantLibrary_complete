## 2. Rules that bind every session of this program

1. No test, ever, in this program: no unit or integration test runner, no browser automation, no emulator, no Gradle test task, no Docker stack, no app launch for validation. Allowed, because they hold no slot: the hygiene checker, the harness parity checker, the batch-package checker, markdown link checkers, formatters and linters, type checks that produce nothing to run, and the Kit's static design checks. A step that believes it needs a test records the need as a row in rework/REGISTER_deferred-validations_2026-10-13.md (what would be run, by which skill, for which change, after which lane) and goes on. Those rows become the first batches when batch work resumes.
2. Sources are read-only (§1). A finding about a source is a row in the reuse register, never an edit in the source.
3. The CLAUDE.md rule blocks apply to every file this program creates or moves: `<TYPE>_<topic>_<YYYY-MM-DD>.md` in a declared root with its INDEX.md line in the same commit; a new root, exemption, hold, release or allowlist entry is a D-YYYY-MM-DD-nn entry in that repository's hygiene/HYGIENE_DECISIONS.md (next free id by grep over the repository); a rename is git mv plus a mapping-table row plus a reference sweep; a PROMPT/PROMPTS file states scope, constraints, done-when and commit line and never a proof surface. The checker under scripts/hygiene/ is the contract; run it after every file move and before every commit that touches markdown.
4. A prompt never overrides a skill. Phase B lanes are runbook steps, not run-batch batches, precisely because run-batch would demand each row's named validation. Every batch-package edit still follows plan-batch's row schema and is recorded as a decision in the package's STATE.md; the validation cells are never widened or deleted, only pointed at by the deferred register.
5. One writer per repository at a time. Lanes that write different repositories run in parallel in place. Two lanes that need the same repository either serialize or the second gets a worktree of that repository: `git -C <repo> worktree add C:\Programmierung\SW_Development_wt\<repo>-<lane> -b rework/<lane> <base>`, merged back fast-forward by you at a boundary and removed afterwards. Submodule commits land on each suite's main; the superproject bumps gitlinks in one commit per step, with the ledger flip in the same commit. No session pushes (Q-G-03).
6. Parallel sessions: read-only analysis lanes fan out as subagents in one message, each with a fixed return schema (a coverage table read / partly read / not read with reasons; findings with file:line; candidates with verdicts; questions with options and a recommended (a)). Write lanes run as subagents with worktree isolation, or as headless `claude -p` processes started in the background from the lane's cwd with the model and effort the runbook row names, each writing its report into the lane's deliverable; check `claude --help` once for the exact flags. At most four write sessions at once beside you; one Fable 5.1 session at a time (you). A subagent's verdict is a claim: verify once on the critical path. A session that dies short of context commits what it has, marks the rest *not read*, and is restarted with the same block.
7. Operator questions never block you. Every question is a row `Q-<lane>-<nn>` in rework/REGISTER_operator-questions_2026-10-13.md with options and a recommended (a). A step that depends on one is marked `waits Q-...` in the runbook and skipped until the answer is recorded verbatim with its date in the runbook's §Q; every other step proceeds. Keep an operator-session prompt current in the runbook's §O: a fresh Opus 5.5 · high session that reads the register, walks the operator through the open questions in dependency order with the options and your recommendation in plain words, records the answers verbatim, flips the rows, and commits. Re-read the register at every wave boundary and release the waiting steps.
8. Bytes and shells: write a package or suite file back with its own line endings (`git ls-files --eol` before committing; most package files are CRLF); never a text-mode rewrite, never a core.autocrlf change. Never put Windows paths or backslash escapes into Python inside a Bash heredoc: write the script with the Write tool, strip the CR it adds (`sed -i 's/\r$//'` on scratch files only), run the file. `git grep --recurse-submodules` from the superproject returns superproject hits only: grep each submodule with `git -C`. Permission denies `git checkout --`, `git restore`, `git stash` and `rm` in compound commands: restore a file by writing `git show HEAD:path` out through Python.
9. Models: you are Fable 5.1 · high (xhigh for R-3). Analysis lanes Opus 5.5 · high; mechanical census lanes Sonnet 5.5 · high; execution lanes Opus 5.5 · high; IA, mockup and design-decision steps Opus 5.5 · xhigh; operator sessions Opus 5.5 · high. Every runbook row names its model and reasoning.
10. Tell the operator in two lines when a step starts or finishes and in which repository. The runbook's ledger is the only status. At every stop you cannot continue from, write a HANDOVER into handovers/ whose continuation section states scope, constraints, done-when and the commit line.
