# Operator questions — PlantLibrary master rework (register of record)

*Opened 2026-10-13 at `R-0` by the orchestrating session (`PROMPT_master-rework-kickoff_2026-10-13.md` §2 rule 7).
A question never blocks the program: a step that depends on one is marked `waits Q-…` in the runbook's §3 and
skipped until the answer is recorded here verbatim with its date; every other step proceeds. The operator session
(runbook §O) walks the open rows in dependency order, records the answers verbatim, flips the state and commits.
The runbook's §Q mirrors this table; this file is the register of record. Rows are written by the orchestrator (from the kickoff, the audits, or a lane's proposed rows); a lane never writes this file. A † in an Options cell marks a recommendation the orchestrator refined at `R-3` where lanes disagreed or added evidence.*

## How to read a row

| Column | Meaning |
|---|---|
| ID | `Q-<lane>-<nn>`; `G` is the program lane (seeded by the kickoff prompt §4), `A1`…`A9`, `B1`…`B8`, `C1` the lanes that raise one |
| Question | What the operator decides, in plain words |
| Options | `(a)` is always the recommendation; others follow |
| Why (a) | The reasoning for the recommendation, short |
| Waits | The runbook steps marked `waits Q-…` on this row |
| Source | The audit row or step that raised it (what to read before answering) |
| When | The latest step it must be answered before; the ordering key of the operator session |
| State | `open` · `answered` · `withdrawn (<why>)` · `superseded (<Q id>)` (folded into another row; never asked) |
| Answer (verbatim, date) | The operator's words, unedited, in quotes, with the date and UTC time and how it was asked (`§O session <name>` or `orchestrator chat`), and the option it resolves to; `(a)` alone only when the operator said exactly that; a one-line answer for many rows is quoted in each row it resolves |
| Reading | Empty unless the answer departs from the options; then the orchestrator's reading and the step it inserts |
